**상태: 계획만 확정. 실행은 사용자 승인 후 (D1).**

- 사전 점검 결과: [2026-11-12_c5e_prep_result.md](2026-11-12_c5e_prep_result.md)
- 리허설은 실제 DB 덤프 사본에서만 했고, 모두 PASS

## 0. 범위·전제

**적용 범위**
- `database/migration/08_collect_settings.sql` 하나만 적용한다.
- 06(Protocol Menu Action)은 G4로 별도 결정한다.
  - 08은 06이 없어도 동작한다 (C5b N-1~3, C5e 리허설에서 확인).
  - 다만 C5c 화면 Action을 쓰려면 06이 필요하다. 그래서 06을 함께 적용할지 결정이 필요하다 (아래 Q1).

**대상 환경**
- PC-B MariaDB 10.6.16, DB `juprovider` (39 tables, 1.06 MB)
- 비밀 값은 `setenv.bat`에서 환경변수로만 읽는다.

**호환성 (현재 배포 서버)**
- 현재 배포된 서버는 WAR 10/25 버전(main 계열)이다.
- 08 적용 후에도 그대로 동작한다. 근거:
  - 08은 컬럼을 테이블 끝에 추가만 하고, 기존 값은 비어 있는 행만 정정한다.
  - main 코드에는 대상 테이블에 대한 위치 기반 INSERT나 `SELECT *`가 없다 (코드 확인).
  - C5a 서버를 08 적용 DB에서 돌린 실서버 회귀가 43/43 PASS였다 (C5b G-2).

## 2. 백업

**절차**
- 명령: `mysqldump --single-transaction --routines --triggers --hex-blob juprovider`
  - 이벤트가 있으면 `--events`를 추가한다. 현재는 이벤트 0개다.
- 보관 위치: `C:\MyData\MyDev\backup\c5e_<날짜시각>\` (로컬 전용, 공유 저장소에 올리지 않음)
- 저장할 것: 덤프 파일, SHA256, 적용 전 CHECKSUM 목록

**백업 확인**
- 같은 덤프를 임시 DB에 복원한 뒤, 전체 덤프 해시와 CHECKSUM이 실제 DB와 같은지 본다.
- 리허설 결과 R-2 PASS (덤프·복원 각 약 1초).

**주의**
- `log_bin=OFF`라서 시점 복구(PITR)가 안 된다.
- 따라서 **적용 직전 백업이 유일한 전체 복구 지점**이다.
- 백업과 적용 사이에는 서버를 멈춰 두어 변경이 생기지 않게 한다.

## 3. 적용 절차 (승인 후)

1. 서버(Tomcat) 중지
2. 사전 점검 P1~P6 실행 → 하나라도 FAIL이면 중단
3. 백업 + 백업 확인
4. `08_collect_settings.sql` 적용
   - 리허설 소요: 0.15초
   - 실패하면 4-1로 간다.
5. 사후 점검
   - 기준: 컬럼 8, 정정 7, 매핑 4, GTEC 간격 200, 코드 7
   - 정정 대상이 아닌 데이터는 그대로인지 확인 (C5b U-9 방식)
   - `08_collect_settings_check.sql` 결과 기록
6. 서버 기동. 이때 배포 버전은 그대로 둔다 (C5c 배포는 D2에 따라 별도 승인).
7. 결과 보고. 백업 파일은 C5c·C5d 배포가 안정된 뒤 정리한다.

## 4. 복구

| 단계 | 언제 | 방법 | 리허설 |
|---|---|---|---|
| 1차 | 08 적용 후 문제 발견 (데이터는 정상) | `08_collect_settings_down.sql` 실행. 정정 전 값을 백업 테이블에서 되돌리고, 추가한 컬럼·테이블·코드를 제거한다. 재실행해도 안전 | R-5 PASS: down 후 상태가 08 적용 전과 덤프 기준으로 완전히 같음 (0.12초) |
| 2차 | 1차 실패, 또는 데이터 이상 | 서버 중지 → 2절 백업으로 전체 복원 → 적용 전 CHECKSUM과 비교 | R-6 PASS: 08 적용 DB를 백업으로 복원 → 실제 DB와 덤프 해시 동일 (0.8초) |

- 08 적용 후 화면에서 입력한 수집 설정은 1차·2차 복구 때 함께 지워진다.
- 복구가 필요하면 C5c 서버는 배포하지 않는다. C5c 서버는 08 컬럼이 있어야 동작한다.

## 5. 결정 필요

- **Q1**: 06을 C5e에서 함께 적용할지 (G4)
  - 리허설은 06 → 08 순서로 PASS했다.
  - C5c 서버의 Protocol 화면 Action을 쓰려면 06이 필요하다.
- **Q2**: 적용 시각과 서버 중지 가능 시간
  - 실제 소요는 백업·적용·점검을 합쳐 약 1분 이내다.

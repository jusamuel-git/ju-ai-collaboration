## 2. W-2 400 원인 (DB 문제 아님)

- 응답 본문: `400 {"success":false,"message":"아이디 또는 비밀번호가 올바르지 않습니다."}` → 로그인 실패 처리 문구. DB 사용자 조회가 정상 수행된 결과.
- 배포 WAR는 **10/25 빌드** (69.7 MB)로 main `fce5048`보다 이전 버전. 이 버전은 로그인 실패를 400으로 응답한다 (main은 401). 확인 스크립트의 기대값을 main 기준으로 잡은 것이 원인.
- 같은 배포본은 없는 경로·빈 본문도 500으로 응답한다 (`Exception` 일괄 처리). 08과 무관한 기존 동작.
- 한계: 적용 전 같은 배포본으로 로그인 실패를 호출한 기록이 없어 "적용 전도 400" 직접 비교는 없음. 근거는 응답 문구와 배포 클래스 확인.

## 3. 보고만 (조치 안 함)

- **배포 WAR(10/25)는 `/api/core/sync/devices`를 Client Key 없이 200으로 응답**한다. main `SecurityConfig`는 Client Key를 요구한다. 배포본이 SEC 이전 버전이라 생긴 기존 상태. C5c 서버 배포(D2) 때 해소 예정이며 그 전까지 8081 외부 노출 주의.
- `ai_c5e_apply.ps1` 5단계가 `startup.bat` 출력 대기로 끝나지 않아 최종 표시(`C5E-APPLY-DONE`)가 로그에 없다. 1~4단계 판정은 로그에 모두 기록됨. 5단계는 `ai_c5e_check5.ps1`로 따로 확인했다. 열린 apply 창은 닫아도 된다 (Tomcat은 별도 창).
- 백업 파일은 C5c·C5d 배포 안정 후 정리 (계획 3절 7).
